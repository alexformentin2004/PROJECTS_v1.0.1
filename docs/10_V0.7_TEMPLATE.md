# 10 — v0.7 Template

## Obiettivo
Riutilizzare strutture progettuali senza copiare date, ID o stato operativo del progetto sorgente.

## UX
`Nuovo progetto` apre una scelta:
1. Progetto vuoto.
2. Uno dei template disponibili.

La schermata Progetti espone anche `Modelli`, mentre il dettaglio di ogni progetto espone `Salva come template`.

## Template predefiniti
- Sviluppo app
- Acquisto importante
- Viaggio
- Nuovo PC
- Progetto auto
- Obiettivo complesso

Sono record locali `source = builtin`, `locked = true` e non possono essere cancellati dall'utente.

## Template personali
Un progetto esistente può diventare un template personale. Vengono acquisiti:
- priorità e tag di default;
- durata relativa;
- milestone non annullate;
- task non annullati;
- checklist;
- relazione task→milestone;
- dipendenze tra task.

Non vengono copiati:
- note;
- riferimenti;
- Timeline;
- budget;
- stati completati;
- UUID originali.

## Date relative
Le date sono convertite in `offsetDays` rispetto alla data di inizio del progetto sorgente. Se questa manca, si usa la prima data utile della struttura; in assenza di date viene usato il giorno corrente come base tecnica.

Durante l'applicazione del template:
- l'utente sceglie la nuova `startDate`;
- milestone e task ricevono nuove date tramite `startDate + offsetDays`;
- elementi senza scadenza restano senza scadenza;
- la scadenza progetto può essere calcolata da `durationDays`.

## Integrità relazioni
I blueprint usano chiavi logiche interne (`m_*`, `t_*`).

Creazione:
1. nuovo progetto;
2. nuove milestone e mappa `milestoneKey → UUID`;
3. nuovi task senza dipendenze e mappa `taskKey → UUID`;
4. ricostruzione delle dipendenze usando i nuovi UUID;
5. salvataggio origine template sul progetto.

Se una fase fallisce, il progetto parzialmente creato viene eliminato insieme ai dati collegati.

## Compatibilità
- appVersion: `0.7.0`
- schemaVersion: `1`
- dbVersion: `1`
- nessuna migrazione dalla v0.6
