# 07 — PROJECTS v0.4: Task, Checklist, Milestone e Dipendenze

## Obiettivo
Trasformare PROJECTS da gestore del ciclo di vita dei progetti a strumento operativo quotidiano.

## Task
Ogni task appartiene obbligatoriamente a un progetto e può opzionalmente appartenere a una milestone.

Campi implementati:
- titolo;
- descrizione;
- stato;
- priorità;
- data e ora di scadenza;
- checklist;
- milestone;
- dipendenze da altri task dello stesso progetto.

## Checklist
Le checklist restano incorporate nel task. Non sono task figli e non partecipano direttamente a TODAY/Events.
Servono per spezzare un'attività in passaggi piccoli senza aumentare il rumore operativo.

## Dipendenze
Campo persistito: `dependencyIds`.

Regole:
- stesso progetto;
- no self-link;
- no cicli;
- no nuove dipendenze verso task `cancelled`;
- `blocked` è derivato;
- completamento non consentito finché almeno un prerequisito non è `completed`;
- eliminazione/annullamento di un prerequisito rimuove il legame dai dipendenti.

## Milestone
Una milestone rappresenta un traguardo, non una singola attività.
Stati:
- `planned`;
- `active`;
- `completed`;
- `cancelled`.

I task puntano alla milestone tramite `milestoneId`.
Eliminare la milestone non elimina i task.

## Avanzamento
Task:
- completed = 100%;
- checklist presente = checked / totale;
- altrimenti 0%.

Milestone:
- media progresso dei task collegati, esclusi `cancelled`.

Progetto automatico:
- media progresso di tutti i task del progetto, esclusi `cancelled`.

## ALEX HUB
La v0.4 rende concreti i contratti già predisposti:
- TODAY riceve task oggi/scaduti e milestone imminenti;
- Hub Summary conta task di oggi/scaduti;
- Insights emette `project_progress`;
- Events espone scadenze task, milestone e progetto;
- Quick Action `Nuovo task` è operativa.
