# 12 — v0.9 ALEX Integration Layer

## Obiettivo
Trasformare i contratti ALEX già presenti in PROJECTS in un layer pubblico, versionato e verificabile, mantenendo PROJECTS completamente autonoma.

## File principale
`js/services/integration-service.js`

Il file non contiene logica di business duplicata: orchestra gli adapter esistenti in `integration.js` e il backup in `backup-service.js`.

## Descriptor
`getModuleDescriptor()` restituisce identità, versioni, namespace, modalità standalone/offline, contract version e capability.

Protocollo corrente:
- `protocol`: `alex-hub-module`
- `protocolVersion`: `1`
- `moduleApiVersion`: `1.0.0`

## Contratti
| Contratto | Versione | Funzione principale |
|---|---:|---|
| Today | 1 | `getTodaySummary()` |
| Hub Summary | 1 | `getHubSummary()` |
| Insights | 1 | `getInsights()` |
| Events | 1 | `getEvents()` |
| Quick Actions | 1 | `getQuickActions()` |
| Global Backup | 1 | `getGlobalBackupContribution()` |
| Action Target | 1 | `parseActionTarget()` / `dispatchActionTarget()` |

## Quick Actions
Le quick action sono normalizzate con `sourceModule: projects` e target stabili:
- `projects/action/new-task`
- `projects/action/new-project`

## Deep-link / action target
Sono supportati:
- `projects/project/<projectId>`
- `projects/project/<projectId>/task/<taskId>`

La PWA accetta inoltre `?alexTarget=<target>` e rimuove il parametro dalla URL dopo il dispatch.

## Bridge runtime
All'avvio `app.js` registra:

`globalThis.ALEX_HUB_MODULES.projects`

Il bridge include:
- descriptor;
- Today Summary;
- Hub Summary;
- Insights;
- Events;
- Quick Actions;
- Integration Snapshot;
- Global Backup Contribution;
- Action resolver/dispatcher.

La registrazione è opzionale e non richiede che l'HUB sia presente.

## Integration Snapshot
`getIntegrationSnapshot()` restituisce un payload coerente generato nello stesso momento. Per impostazione predefinita include Today, Hub Summary, Quick Actions, Insights ed Events; `todayOverview` è opzionale.

## Backup globale
`getGlobalBackupContribution()` produce:

```json
{
  "format": "alex-hub-module-backup",
  "formatVersion": 1,
  "moduleId": "projects",
  "namespace": "alex.projects",
  "appVersion": "0.9.0",
  "schemaVersion": 1,
  "exportedAt": "...",
  "storageKey": "modules.projects",
  "payload": { "moduleId": "projects", "data": {} }
}
```

Il futuro ALEX HUB potrà assemblare:

```json
{
  "modules": {
    "projects": { "...": "contributo PROJECTS" },
    "money": { "...": "contributo MONEY" }
  }
}
```

senza collisioni di chiavi.

## Diagnostica
`getIntegrationDiagnostics()` verifica:
- Hub Summary compreso tra 2 e 5 elementi;
- Today con campi obbligatori;
- Insights normalizzati e `sourceModule=projects`;
- Events normalizzati e `sourceModule=projects`;
- Quick Actions normalizzate e `sourceModule=projects`.

La schermata Impostazioni rende visibili protocollo, API version, namespace, capability, versioni contratto e conteggi correnti.

## Compatibilità
- `schemaVersion`: 1 invariata;
- `dbVersion`: 1 invariata;
- nessuna migrazione da v0.8;
- nessun nuovo object store;
- nessuna dipendenza di rete;
- funzionamento standalone invariato.
