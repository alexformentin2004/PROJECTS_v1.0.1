# 09 — v0.6 Contesto progetto

## Obiettivo
Aggiungere informazioni utili attorno all'esecuzione senza trasformare PROJECTS in Note, File o MONEY.

## Note
- entità autonoma nello store `notes`;
- collegate obbligatoriamente a un progetto;
- titolo + body semplice;
- `pinned` per evidenziare decisioni importanti;
- ordinate con pinned prima, poi aggiornamento più recente.

## Riferimenti
Store `references` con tre tipi:
- `link`: URL http/https;
- `file_reference`: nome file + posizione/hint + eventuale link condiviso;
- `text_reference`: informazione breve non documentale.

PROJECTS non salva il contenuto binario dei file e non assume di possedere handle permanenti verso File di iOS.

## Timeline
Lo store `timelineEntries`, già usato tecnicamente dalle versioni precedenti, viene reso visibile.

La UI:
- ordina per `occurredAt` decrescente;
- mostra gli ultimi 20 eventi significativi;
- filtra aggiornamenti generici `task.updated`, `milestone.updated`, `note.updated`, `reference.updated`;
- conserva comunque tutti i record nel database;
- permette eventi manuali `manual.note` per decisioni significative;
- permette di eliminare solo gli eventi manuali.

## Budget
Campo opzionale dentro `Project`:
```json
{
  "enabled": true,
  "currency": "EUR",
  "planned": 2000,
  "spent": 1270.5,
  "note": ""
}
```

Derivati, non salvati:
- `remaining = planned - spent`;
- `percentSpent = spent / planned * 100`.

Non vengono registrate transazioni. MONEY potrà diventare in futuro la fonte delle spese reali. Se `spent > planned` con budget attivo, il motore health considera il progetto `at_risk` salvo condizioni più prioritarie come `blocked` o `overdue`.

## Compatibilità
- appVersion `0.6.0`;
- schemaVersion `1`;
- dbVersion `1`;
- nessun nuovo object store;
- nessuna migrazione dalla v0.5.
