# 11 — v0.8 Export / Import e migrazioni

## Obiettivo
Rendere PROJECTS portabile e recuperabile senza dipendenze esterne, rispettando l'ALEX Integration Standard.

## Export JSON
Ogni export contiene obbligatoriamente:
- `moduleId`;
- `appVersion`;
- `schemaVersion`;
- `exportedAt`;
- `settings`;
- `data`;
- `metadata`.

`data` contiene gli store funzionali completi: progetti, milestone, task, note, riferimenti, timeline e template.

`metadata` include anche:
- `exportFormatVersion`;
- namespace e database del modulo;
- `dbVersion`;
- conteggi record;
- record dello store metadata.

## Import guidato
Il flusso è:
1. scelta file JSON;
2. parsing locale;
3. validazione struttura e modulo;
4. controllo schema supportato;
5. controllo ID duplicati;
6. controllo relazioni progetto/milestone/task;
7. controllo dipendenze e cicli;
8. anteprima con conteggi;
9. scelta `Unisci` o `Sostituisci`;
10. export automatico pre-import;
11. scrittura atomica IndexedDB;
12. reinizializzazione metadata/default/template built-in.

Nessun dato viene inviato a server esterni.

## Modalità Unisci
- conserva i record presenti localmente;
- aggiunge quelli mancanti dal backup;
- quando esiste lo stesso `id`, mantiene il record con `updatedAt` più recente;
- il risultato finale viene validato nuovamente prima di essere scritto.

Questo secondo controllo impedisce che la risoluzione dei conflitti produca relazioni incoerenti.

## Modalità Sostituisci
Tutti gli store PROJECTS vengono sostituiti con quelli del backup nella stessa transazione IndexedDB.

Dopo la sostituzione PROJECTS:
- aggiorna il record metadata del modulo alla versione app corrente;
- ripristina eventuali settings di default mancanti;
- ripristina template built-in mancanti o da aggiornare.

## Backup preventivo
Prima di qualunque import viene creato un file:

`PROJECTS_pre_import_YYYY-MM-DD_HHMM.json`

che rappresenta lo stato locale immediatamente precedente all'operazione.

## Migrazioni schema
La pipeline `migrateBackup()` applica trasformazioni sequenziali da una `schemaVersion` meno recente a quella corrente.

Nella v0.8:
- schema corrente: `1`;
- tutte le versioni PROJECTS v0.1-v0.8 usano schema `1`;
- nessuna migrazione concreta è quindi necessaria oggi;
- un backup con schema futuro viene respinto per evitare corruzione.

Quando nascerà schema `2`, verrà aggiunta una migrazione `1 → 2` senza modificare il contratto esterno.

## Sicurezza e limiti
- dimensione massima import singolo: 50 MB;
- solo JSON locale;
- `moduleId` deve essere `projects`;
- niente import parziale;
- niente rete necessaria;
- l'operazione database è atomica.
